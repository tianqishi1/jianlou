# 捡漏（jianlou）技术实现方案

> 版本：M0 · 2026-11-23 · 配套：《产品设计方案》

## 1. 架构总览：LLM 解析，脚本算账

```
用户输入(截图/链接/文字)
   │  宿主多模态/浏览/搜索（绿区源）
   ▼
[LLM 层] 语义解析 → 结构化输入 JSON(item/ask/anchors) + 价格锚(带来源/日期)
   │
   ▼
[确定性引擎] skill/scripts/jianlou.py（零依赖 Python 3.10+）
   value_hint → 红旗规则 → fair_value → 总成本 → 净漏值率 → 分级/拒答
   │
   ▼
捡漏卡片 JSON → 宿主按 assets/card-template.md 渲染
```

设计哲学与 jue/heng-erp 一脉相承：**LLM 永不直接算账**。M0 评测实证：让 LLM 手算结论（direct 消融）准确率仅 70%（经济账全错），LLM 解析+引擎计算（parse）达 100%。确定性层还保证阈值可审计、可回归、可门禁。

## 3. 数据契约（引擎输入 schema）

```json
{"item": {"title","category","condition","accessories_missing[]","defects[]",
          "warranty_months_left","distance_km","pickup"},
 "ask": {"price","shipping_fee","deposit","offplatform_contact","account_age_days",
         "images_real","story","urgent_pressure"},
 "anchors": [{"kind":"sold|used|new","low","high","source","date"}]}
```

- 锚有效性：low/high ≥0 且 source、date 非空，否则无效；无有效锚 → 拒答；
- condition ∈ {全新, 几乎全新, 轻微使用痕迹, 明显使用痕迹, 故障/配件机, 未知}，未知 → 拒答。

## 4. 确定性规则（全部经验值，改动须过门禁）

### 4.1 估值

```
base = 锚中位数（优先级 sold > used > new×0.60）
fair = base × 成色系数 × (1 − 配件罚 − 瑕疵罚 + 保修补)
成色系数：全新1.10 / 几乎全新1.00 / 轻微0.85 / 明显0.65 / 故障0.30
配件罚 3%/项 cap15%；瑕疵罚 8%/处 cap30%；保修补 0.5%/月 cap6%
```

### 4.2 成本与分级

```
transport = min(pickup基价{easy:0,medium:30,hard:80} + max(0,km−10)×2, 150)
total = price + shipping + deposit + transport + 15(时间)
net = (fair − total)/fair
net≥25% 且置信非low → worth_go；10–25% → watch；<10% → pass
```

### 4.3 红旗（硬 → avoid，优先于估值；软 → 降置信）

| ID | 规则 |
|---|---|
| RF_DEPOSIT | deposit > 0 |
| RF_SHIPPING | shipping > max(12, 25%×价值) |
| RF_OFFPLATFORM | 脱离平台 且 (价值≥300 或 账号<30天) |
| RF_TOO_GOOD | 要价≤5%×价值 且 价值≥500 **且叠加≥1其他风险信号** |
| RF_FAKE_IMG | images_real == false |
| RF_STORY | 命中关键词：海关/扣押/罚没/内部渠道/抵债/富二代/盲盒/走私 |

**M0 评测修复的两处关键设计**（badcase 回流）：
1. **value_hint**：红旗价值阈值用"锚中位数（与成色无关）"，而非成色修正后的 fair——否则成色未知时 fair=None 导致高价值引流盘漏判（f4 名牌包案例）；
2. **RF_TOO_GOOD 组合信号**：纯免费的高价值真赠送（无任何风险信号）不触发，必须叠加脱离平台/新号/盗图/叙事/催促/定金之一——否则误杀真实免费相机（a4 案例）。

## 5. 评测体系（双轨 + 消融）

| 轨 | 内容 | 工具 |
|---|---|---|
| Track A | 结构化输入 → 引擎 → gold（测规则/估值/拒答） | `jianlou.py eval` |
| Track B-parse | raw listing + 锚 → LLM 解析 → 引擎 → gold（测完整 Skill 分工） | `eval/run_eval.py --mode parse` |
| Track B-direct（消融） | LLM 直接手算结论（归因"为什么需要脚本层"） | `--mode direct` |

- 后端：~/.bailian/config.json 活动 profile（token-plan compatible-mode），模型 qwen3.8-max，enable_thinking=False（jue Phase 0 教训），4 并发 + 重试，原始响应全留痕；
- 评测集：30 例 = 真漏6 / 小漏5 / 无漏5 / 骗局5 / 假免费5 / 边界拒答4；
- 门禁：准确率≥85% · 骗局召回≥90% · 假漏误报≤10% · 拒答正确率100% · 证据可溯源100%；
- badcase 回流：用户"白跑/被骗"反馈 → 新用例 → 回归门禁（eval-pipeline 同构）。

## 7. 小程序移植路径（M1）

- 引擎零依赖纯函数 → 直接移植云函数（Python/Node 重写均可，规则表即配置）；
- LLM 解析层 → 云开发 AI 网关（成长计划免费 Token）；前端截图上传 → OCR/多模态解析 → 同一 schema；
- 内容安全：msgSecCheck/imgSecCheck 必接；类目=工具；不聚合外部 listing（个人主体红线）；
- 变现：流量主激励视频解锁完整卡片；订阅导流社群。

## 8. 测试与 CI

- `pytest tests/`：引擎单测（红旗/估值/拒答/边界）；
- `jianlou.py selftest`：5 断言冒烟；
- 门禁脚本退出码非 0 即失败，可接 CI（GitHub Actions 跑 Track A；Track B 需密钥，手动/夜间跑）。

## 9. 已知限制

- 阈值未用真实成交数据校准（M0+ 回流 20 例真实决策后校准）；
- 评测集 30 例偏小，置信区间宽，扩到 100 例再谈发布；
- 搜索锚质量依赖宿主搜索能力，评测中锚由数据集提供（搜索层单独人工抽检）；
- 实时性：小时级巡检，不承诺分钟级抢先。
