# 捡漏（jianlou）产品设计方案

> 版本：M0 · 2026-11-23 · 配套文档：《技术实现方案》《可行性评估报告 v2.1》（捡漏Skill可行性评估报告.md）

## 1. 定位与本源

**一句话**：把"免费/低价的东西值不值得去拿"做成可解释、可拒答、带证据的判断引擎，先以 Codex Skill 形态落地，再产品化为微信 AI 工具小程序。

本源模型（已验证的爆款结构）：免费物品散落各处 → 有人聚合整理 → 用户付订阅买"省时间+第一时间"。本产品的取舍：

- **拿走引擎**（聚合→筛选→估值→避坑→提醒）：这是 Skill/小程序能承载的核心劳动；
- **不拿壳**（账号/支付/LBS/推送/双边市场）：M0 不做；订阅验证借知识星球/付费群现有轨道；
- **不做**：全网爬虫、代付代拍、"保真/保抢到"承诺、聚合型小程序/App（个人主体资质与内容安全双杀）。

## 2. 用户与场景

| 用户 | 场景 | 频次 | 付费意愿 |
|---|---|---|---|
| 租房/搬家/置家青年 | "免费送的沙发值不值得去搬" | 事件驱动 | 低（广告/免费层） |
| 二手贩子/职业捡漏者 | 抢先发现可转卖的免费/低价货 | 每日 | **高（订阅主力）** |
| 断舍离供给者 | "帮我把闲置如实写清楚送掉" | 事件驱动 | 无（获客钩子） |
| 宝妈/学生 | 母婴/图书低价自提，防邮费盘 | 每周 | 中 |

核心痛点（现有产品没做好的）：
1. 免费≠值得：搬运/距离/时间/瑕疵成本无人算；
2. 假漏与骗局泛滥：邮费盘、定金盘、引流盘、盲盒盘（均有真实曝光案例）；
3. 关键词订阅无语义：不懂"成色/配件/保修/总成本"。

## 4. 核心产品对象：捡漏卡片

```
【结论】值得去拿 / 观望 / 放弃 / 别去 / 无法评估（置信度）
【标的】【价格锚(来源+日期)】【估值明细】【总成本】【净漏值%】
【红旗】硬/软逐条+证据 【行动】话术/验货清单/自提安全清单 【免责声明】
```

分级语义：
- **值得去拿**：净漏值率≥25%，无硬红旗，证据充分；
- **观望**：10–25%，可议价；
- **放弃**：<10%，无漏（含"免费但搬运成本吃掉价值"）；
- **别去**：命中硬红旗（骗局），优先于一切漏值；
- **无法评估**：锚缺失/成色未知 → 拒答，绝不硬给。

## 5. 硬红线（产品宪法）

1. 每个价格锚必须带来源+日期，无锚即拒答；
2. 硬红旗一票否决；
3. 永不代付/代拍/建议预付；
4. Skill 本体零爬虫，只碰绿区数据（用户喂数据+公开页）；
5. 不承诺保真/保抢到/保证收益；输出必带免责声明；
6. 阈值是经验值，改动必须过评测门禁。

## 6. 商业模式与验证

- **工具小程序=规模生意**：免费+广告，需数千 DAU 才有可观收入；冷启动靠微信搜索词/分享/内容获客（原始案例"内容验证后放大"方法）；
- **订阅社群=密度生意**：一城 30–300 付费即达标；付费主力是职业捡漏者；
- 验证门禁（4 周）：≥30 付费、次月留存≥50%、人均月有效申领≥3 次；不达标收缩为纯工具。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| LLM 幻觉价格/手算错误 | 锚强制溯源；**LLM 只解析不算账**，确定性脚本计算（评测已证明必要：direct 模式 70% vs parse 模式 100%） |
| 骗局模式演化 | fraud-patterns 库 + badcase 回流评测集 |
| 国内供给在封闭微信群 | 用户手动转发契约；不做爬虫；海外公开源平行实验 |
| 小程序类目/审核 | 只做纯工具（用户自有数据），个人主体工具类目；不聚合外部 listing |
| 自提人身安全 | 安全清单进每张"值得去拿"卡片 |
| 留存低 | 绑定晨报/盯价高频载体；付费段瞄准贩子 |
